**Как работать дальше**:

- Заход = одна глава (главы 5–8 — по две части), по протоколу `Asm-learning.md` §5.2; прогон всего кода обязателен (FR-5), при одном доступном контуре — правило §5.3 (статус `[L]`/`[M]` + долг §9.4).
- **Вопросы, которые может решить владелец, задавать в той же сессии, где они возникли.**
- **Постановки заданий проверять наравне с текстом** — все, которые что-либо запускают.
- **Учётные расхождения ловятся при загрузке контекста**: §1 и §7 обновлять в конце захода вместе. Каталог врезок `outline.md` §5.1 сверять каждый раз — он расходится с книгой быстрее, чем портится сама книга.
- **Работа в двух машинах параллельно:** незакоммиченные правки может снести merge чужой сессии. Свои учётные правки коммитить в том же заходе.

**Приёмы стендов.** Маковский: `clang -arch x86_64`, `as -arch x86_64` для сообщений, `objdump -s -j __data` (не `.data`), `nm -n`, `od -c` для непечатных байтов, `lldb` батчем, pty для падающих программ и сессий отладчика, `dyld_info -fixups` вместо `readelf -r`. `pdftotext` на маке НЕТ — копии S2 читаются только на виндовой машине. На виндовой машине: **heredoc через `wsl -e bash -lc` ломается** — листинги писать файлами в scratchpad и копировать в WSL через `/mnt/c/...`. Пользователь WSL — `max`, не root, стенд в `$HOME`.

**Осторожно с коммитами:** владелец параллельно ведёт сессии по другим книгам в одном рабочем дереве. Коммитить только формой `git commit <явные пути> -m …`; новый файл сначала `git add <путь>`; после коммита `git status --porcelain` обязан быть пустым — Serena-памяти в `.serena/memories/` отслеживаются и идут **тем же** коммитом (`mem:task_completion` пп. 6, 6a, 6f).

Конвенции соседней книги — `mem:conventions`, окружение — `mem:tech_stack`, завершение захода — `mem:task_completion`, соседняя книга — `mem:c-rust-book-progress`.
