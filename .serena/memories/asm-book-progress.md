**Что вынесло погашение (2026-08-10, контур M, 20 пунктов из 20 + §7.2.6 + 18 постановок заданий):**

1. **Впервые находок больше, чем подтверждений — 12 против 9.** Во всех прежних погашениях было наоборот. **Расхождения начинаются уже при `-O0`**: у `clang` цикл с проверкой **сверху** (без входного `jmp`), деление на два даёт настоящее `idivl` вместо сдвига с поправкой, адрес элемента считается **одной индексной инструкцией**, порядок вычисления аргументов прямой, результат первого вызова живёт в кадре, а не в `%rbx`, и `leave` не порождается **ни разу**. Пять черт, которые глава приписывала ключу `-O0`, принадлежат **gcc при `-O0`**.
2. **Три главных вопроса из четырёх дали расхождение** (в главах 5 и 6 они закрывались совпадением). Состав служебной разметки: из тринадцати строк таблицы §7.1.2 воспроизводятся три; попутно — компилятор M пишет `.asciz` (форму книги), а `.string` пишет gcc, и локальная метка там `L_.str`, то есть префикс **`L` без точки**. `gcc -Q --help=common` заменён на `clang -###`. **`@PLT` на Mach-O не существует** — `error: unsupported symbol modifier in branch relocation`; аналог таблицы связывания есть, секция `__stubs`.
3. **Четвёртый вопрос закрыт исполнением: обе дословные сессии `lldb` сняты.** Найдена ловушка, которой нет на L: точка останова по голому адресу **до** запуска принимается молча и **не срабатывает** (на L `gdb` внятно отказывает). Порядок для M: сначала `process launch --stop-at-entry`, потом `br set -a`. Слайд загрузки под `lldb` равен нулю, так что адрес из `objdump` годится как есть.
4. **Самое ценное совпадение — раскладка структуры** (`размер 24, итого 3001`): смещения 0, 8, 16 подтверждены **трижды независимо** (счётом руками в §6.3.2, выводом gcc, выводом Apple clang). Значит их задаёт ABI, и §6.3.2 переписывать не придётся.
5. **Проверка постановок заданий — шестой улов подряд и рекордный: 11 из 18** (девять привязаны к L, два задеты частично). Новая причина сверх обычной: задания цитируют конкретные числа и мнемоники из листингов, а листинги этой главы целиком принадлежат одному компилятору.
6. **Шестой в книге дефект не по контуру:** Г7.Ч2.З1 просила выписать кодировку `leave` из программы главы 6, а в 37 листингах главы 6 её нет ни разу — книга сама пишет эпилог парой `popq %rbp` / `ret`. Поймано сверкой мнемоник по главам, а не чтением. Попутно: обещание §5.1.2, что в главе 7 байт `c9` встретится в конце почти каждой функции, на M не сбывается вовсе.
7. **Тринадцатая дыра воспроизводимости и первый встречный долг по L.** Глава ссылалась на `sw.c`, которой в тексте не было: скрипт захода 9 проверяет артефакты, чей **вывод** цитируется, а здесь цитировался фрагмент листинга. Правило для скриптов: **проверять и те артефакты, от которых цитируется листинг**.
8. **Ложная тревога стоит проверки наравне с ложным подтверждением.** Два «красных» из четырнадцати оказались дефектами самого скрипта (BSD `awk` не знает `strtonum`; ключ `-x assembler` стоял **после** имени файла, отчего отказ от `@PLT` превратился в мнимое «принят»). Не проверь их — в книгу ушло бы несуществующее расхождение. После правок: **14 сравнений из 14, расхождений ноль.**

**Метод, который работает и переносится на Р2** (подтверждён Р1 и заходами 7–10): сперва машинные сверки, потом чтение по их результатам. Скрипт захода вынимает листинги из markdown, приводит к форме контура, собирает и выполняет блоки прогона со сверкой дословно. Писать заново в каждом заходе; **обязательно в форме «материализовать листинги в пустой каталог и выполнить команды там»**, **проверять непустоту обеих сторон любого сравнения** и **перепроверять расхождения так же, как совпадения**. Начиная с главы 7 добавляется оговорка: на M сверять дословно надо **выводы программ**, а различия кода — описывать во врезках, потому что листинги порождены другим компилятором.

**Приёмы стендов.** Мак (контур M): сборка `clang -arch x86_64`, сообщения ассемблера снимать через `as -arch x86_64` — **без этого ключа `as` разбирает файл как ARM64**, а драйвер `clang` вдобавок печатает временный путь `/var/folders/…` вместо имени файла. Сессии `lldb` — в pty: `script -q /dev/null lldb -b -o … -o …`; батч-режим сам печатает приглашения `(lldb)`, поэтому транскрипт выглядит настоящей сессией и подача по одной строке с паузой (обязательная для `gdb`) **не нужна**. Стенд для сессий держать в **коротком** каталоге: путь попадает в дословный вывод. Имя секции данных — `__data`, символ — `_main`, секция кода — `__text`. `readelf` нет — секции показывает `objdump -h`, заголовок `otool -hV`/`otool -l`. `leaks(1)` под Rosetta готовит отчёт около минуты. `timeout(1)` и `pdftotext` на маке нет; BSD `awk` не знает `strtonum`. Виндовая машина: **heredoc через `wsl -e bash -lc` ломается** — писать `.sh` в scratchpad, копировать через `/mnt/c/...`; **Windows-питон не печатает кириллицу** — гонять через `wsl python3`; осторожно с `pkill -f` в однострочнике `bash -lc`. Сессии `gdb` в pty: команды подавать **по одной с паузой ~0,6 с**, `~/.gdbinit` со `set debuginfod enabled off`, `set style enabled off`, `set pagination off`, `set confirm off`, плюс фильтр escape-последовательностей (§9.2 п. 111).

**Осторожно с коммитами:** владелец параллельно ведёт сессии по другим книгам и на другой машине в одном репозитории. Коммитить только формой `git commit <явные пути> -m …`; после коммита `git status --porcelain` обязан быть пустым — Serena-памяти в `.serena/memories/` отслеживаются и идут **тем же** коммитом (`mem:task_completion` пп. 6, 6a, 6f).
