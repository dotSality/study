**Проектные решения чекпоинтов 4–6:**

1. **Чекпоинт 4 получил собственную программу `move.s`** (в плане было «в snake.s») — ради воспроизводимости: пока игра ходит только по клавише, каждая партия сверяется дословно. Часы появляются только в чекпоинте 5.
2. **Все правила игры — таблица решений по одному байту клетки назначения** (пусто / еда / стена / тело). Координаты не проверяются нигде: границы стережёт стена внутри массива.
3. **Единственное исключение — клетка хвоста:** войти в неё можно, она освободится на этом же шаге. Исключение потребовало правки `step` из 12b (см. ниже).
4. **Тайминг по дедлайну**, `дедлайн += период` (не «сейчас + период»); `poll` получает **остаток** до дедлайна. Наблюдаемое следствие: число шагов задано геометрией поля, а не машиной.
5. **Еда — собственный ЛКГ, зерно в листинге** (12345). Партия — свойство листинга, а не окружения.
6. **Три уровня уборки:** явный `rawoff` (потому что после него `printf`), `atexit` (много веток выхода), обработчик сигнала, поднимающий флаг (сигнал — не нормальное завершение). Предел назван вслух: `SIGKILL` не перехватывается.

**Найденный дефект (свой, из 12b).** `step` гасил клетку хвоста **после** записи головы — а при входе головы на клетку хвоста это одна и та же клетка, и голова стиралась. Ошибка молчит, код 0, на поле змейка без головы при верном кольце. Исправлено двумя инструкциями и меткой; опыт с их удалением стоит в §8.2.4.

**Измерено на L:** ЛКГ — 8 инструкций / 46 байт, с зерном 12345 даёт 235318264, 569910583, 1901863042 → клетки еды (5,4), (4,10), (3,3); младший бит чередуется 0,1,0,1. `now` — 16 инструкций. Партия без клавиш — 10 шагов до стены, наивная схема при 4 клавишах внутри первого кадра — 12 шагов и другая строка гибели. Три пути гибели: SIGTERM с обработчиком — код 0 и `icanon echo`; без обработчика — 143 и `-icanon -echo`; SIGKILL — 137 и `-icanon -echo`. valgrind: 3/3 (2520 байт) без файла рекордов, 4/4 (6616) с ним — разница ровно 4096, буфер потока `fopen`. **Уроки захода 12c:**

1. **Воспроизводимость интерактивной игры — проектное решение, а не свойство.** Четыре решения ради сверки: зерно в листинге, свой генератор, шаг по дедлайну, подача клавиш **посередине между тиками** (при периоде 150 мс расписание 0,08 / 0,22 / 0,97 / 1,84, запас ±70 мс). Каждая цитируемая партия прогнана по пять раз и совпала по md5.
2. **Сверку надо вести в обратную сторону.** `verify.py` вынимает `snake.s`, `play.py` и `sigtest.sh` **из markdown главы**, собирает в пустом каталоге, порождает три сборки для опытов и прогоняет все 16 цитируемых команд: **41 проверка, 0 расхождений**. Это доказывает то, что нужно читателю, а не то, что удобно автору. Скрипт в гит не идёт — воссоздаётся по §9.5.
3. **Дефект нашёлся при написании опыта, а не при отладке.** Правило «убери одну строку» заставило проверить случай, до которого обычная игра не доходит.
4. **Цитировать только те команды, чей вывод зависит от книги.** К номеру процесса valgrind добавилась метка времени `ls -l` — заменена на `wc -c`.
5. **Два дефекта измерителя дали ложный отказ, а не ложное «совпало»** — впервые за девять заходов. Причина: обе проверки строились на точном равенстве. Нормализацию применять к **обеим** сторонам сравнения.

**Приёмы стендов.** Виндовая машина: WSL-дистрибутив зовётся **`Ubuntu-24.04`** (не `Ubuntu`), пользователь **`max`, не root** — стенд в `~/asmNN`, `/root` недоступен. **Переменные оболочки в `wsl -d … -- bash -lc '…'` из Git Bash приходят пустыми** (цикл `for f in ...; do` там же не работает), а heredoc и обратные кавычки ломаются — писать `.sh`/`.py`/`.s` в scratchpad, копировать **хардкоженым** путём `/mnt/c/...`, затем `sed -i 's/\r$//'`, всю логику с переменными, циклами и регулярками держать в файле скрипта. Экранирование `\x03` через два уровня кавычек не выживает — расписание нажатий передавать из файла-скрипта в одинарных кавычках. Путь `/mnt/c/...` в аргументе требует `MSYS_NO_PATHCONV=1`. `set -e` в проверочных однострочниках не ставить. Сессии `gdb` — в pty питоновским драйвером; интерактивные программы — драйвером `play.py` (расписание отсчитывается **от первого вывода программы**), сигналы им шлёт фоновый `pkill`, а сама программа остаётся на переднем плане. `strace` в WSL1 нет. Мак (контур M): сборка `clang -arch x86_64`, сообщения ассемблера через `as -arch x86_64`; `lldb` в пакетном режиме — `lldb -b -o 'команда' … ./prog`; **оболочка zsh не делит слова при подстановке переменной** (споткнулся об это 2026-08-20: `./sigtest.sh $c` при `c="snake TERM"` уходит одним словом); `script` из BSD — форма `script -q /dev/null команда аргументы`, ключа `-c` нет; интерактивную программу без настоящего tty на stdin запускать нельзя (иначе `script` шлёт EOF и в вывод лезет `^D\b\b`) — годится питоновский драйвер на `pty.openpty()`; `od -c` в UTF-8 локали печатает многобайтные символы символами — для восьмеричных кодов нужен `LC_ALL=C`; `wc` дополняет число пробелами слева; `leaks -atExit -- ./prog` работает и ловит утечку, **если программа сама не держит указатель** (иначе «0 leaks» из-за достижимости); ASan утечек не ищет вовсе;  `readelf`/`timeout`/`pdftotext` отсутствуют (правки при загрузке — `dyld_info -fixups`, сегменты — `otool -lv`), BSD `awk` не знает `strtonum`, BSD `/usr/bin/time` не знает `-f`, BSD `od` форматирует `-An -tx1` иначе GNU, BSD `script` имеет другой синтаксис, `leaks(1)` под Rosetta медленный и часто не завершается.
