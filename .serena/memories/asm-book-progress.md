**Четыре проектных решения, принятых пробой (действуют для 12b/12c):**

1. **Еда — собственным ЛКГ, а не `rand()`.** `состояние × 6364136223846793005 + 1442695040888963407`, значение — `shrq $33`. С зерном 12345: 235318264, 569910583, 1901863042, … Причина: библиотечный генератор — чужой код, у двух libc он разный, и дословно одинаковых кадров на двух контурах дать не может; §2 п. 4 требует дословного вывода, а врезка не спасает — расходится не оформление, а сама партия. Библиотечный `rand()` на L (зерно 12345): 383100999, 858300821, 357768173, … — оставлен как доказательство для врезки.
2. **Часы — `clock_gettime(CLOCK_MONOTONIC)`**, идентификатор в `.equ`. Альтернатива `gettimeofday` константы не требует, но ширина `tv_usec` — `suseconds_t` и на M не мерялась. Одна `.equ` правится врезкой, разъехавшееся поле структуры — нет.
3. **Чекпоинт 3 обязан дать свой выход:** `stty raw` снимает `isig`, `Ctrl-C` приходит байтом 3, программа живёт дальше. Без своего выхода из игры не выйти вовсе.
4. **Чекпоинт 6 — на трёх измеренных путях:** обычный возврат терминал восстанавливает; гибель от SIGSEGV (139) оставляет `-echo -icanon`; обработчик сигнала обязан только поднимать флаг (список безопасных функций — S7, `system` в него не входит), а восстанавливает обычный путь выхода. `atexit` из ассемблера работает и покрывает `exit()` из глубокой ветки (проверено: код 3, терминал цел).

Попутно сняты обе рубрики «типичные ошибки» по таймингу: наивная схема «таймаут = кадр» даёт кадр с нажатием в 1 мс вместо 100; схема по дедлайну держит темп (шаги 300/600/902/1200/1500 при трёх нажатиях внутри первого периода).

**Уроки захода 12a:**

1. **Проба до письма окупается.** Главное её решение — не измеренное число, а отказ от `rand()`. Найдись это в середине 12c, переписывать пришлось бы все кадры части.
2. **Седьмой подряд дефект собственного измерителя, и снова ложное «совпало»**: флаги терминала извлекались построчно, а `stty -a` печатает их через пробел — сравнивались две пустые строки, и после гибели программы измеритель отчитался «терминал восстановлен». Ловится правилом 2026-08-09 («докажи, что было что сравнивать»); в измеритель добавлена остановка при пустом снимке.
3. **Интерактивную программу в сценарном прогоне не переводить в фон:** фоновый процесс неинтерактивного `bash` получает stdin из `/dev/null`, `stty` в нём отказывает, `poll` возвращает готовность мгновенно. Сигнал слать фоновым `pkill`, программу держать на переднем плане.
4. **Русские подписи в кадре — UTF-8, по два байта на букву**, поэтому длина строки в байтах ≠ ширина в колонках; арифметику поля вести по колонкам.

**Приёмы стендов.** Виндовая машина: WSL-дистрибутив зовётся **`Ubuntu-24.04`** (не `Ubuntu`), пользователь **`max`, не root** — стенд в `~/asmNN`, `/root` недоступен. **Переменные оболочки в `wsl -d … -- bash -lc '…'` из Git Bash приходят пустыми** (`SP=…; cp "$SP"/*` копирует из `/`), а heredoc ломается — писать `.sh`/`.py`/`.s` в scratchpad, копировать **хардкоженым** путём `/mnt/c/...`, затем `sed -i 's/\r$//'`, всю логику с переменными и циклами держать в файле скрипта. Путь `/mnt/c/...` в аргументе требует `MSYS_NO_PATHCONV=1`, иначе Git Bash конвертирует его в виндовый. `set -e` в проверочных однострочниках не ставить (программы книги по замыслу возвращают ненулевые коды). Сессии `gdb` — в pty питоновским драйвером; интерактивные программы — драйвером `ptydrv.py` (расписание нажатий отсчитывается **от первого вывода программы**, не от запуска процесса, — поправка Rosetta из требований §7.2 п. 7). Мак (контур M): сборка `clang -arch x86_64`, сообщения ассемблера через `as -arch x86_64`; `lldb` в пакетном режиме — `lldb -b -o 'команда' … ./prog`; оболочка zsh не делит слова при подстановке переменной; `readelf`/`timeout`/`pdftotext` отсутствуют (правки при загрузке — `dyld_info -fixups`, сегменты — `otool -lv`), BSD `awk` не знает `strtonum`, BSD `/usr/bin/time` не знает `-f`, BSD `od` форматирует `-An -tx1` иначе GNU, `leaks(1)` под Rosetta медленный и часто не завершается.
