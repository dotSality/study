6. **`git add -A` / `git commit -a` / `git add .` в этом репозитории ЗАПРЕЩЕНЫ.** Стажировать только явно перечисленные пути своего захода. Причина (инцидент 2026-07-27): владелец ведёт параллельные сессии в одном рабочем дереве, файл чужого захода появился между `git status` и `git add -A` и уехал в чужой коммит. `git status` перед коммитом не защищает — дерево меняется под руками. Если чужой файл всё же попал в коммит: `git reset --soft HEAD~1`, затем коммит заново с явными путями (рабочее дерево при этом не трогается, файл цел).
6a. **`git commit --amend` без путей так же опасен, как `add -A`** (инцидент 2026-07-31): amend берёт **весь индекс**, а в индексе почти всегда лежат staged файлы параллельной сессии — в коммит уехал 41 чужой файл. Правильно: `git commit <путь1> <путь2> -F -` (partial commit — чужие пути остаются в индексе нетронутыми); для правки сообщения — `git reset --soft HEAD~1` и такой же partial commit заново. Проверка после коммита: `git log -1 --stat` должен показывать только свои файлы, `git diff --cached --name-only | wc -l` — прежнее число чужих staged.
6b. **Сообщения коммитов писать через `-F -` с heredoc** (`<<'EOF' … EOF`): инструмент Bash — это Git Bash, PowerShell-here-string `@'…'@` там не работает и `@` уезжает в заголовок коммита.
6b-1. **Трейлеров `Co-Authored-By` и `Claude-Session` в сообщениях НЕ ставим** (указание владельца 2026-08-02). Сообщение — заголовок плюс тело в 1–3 строки, и больше ничего. Если рабочая инструкция агента требует трейлеров, здесь она перекрыта указанием владельца: история репозитория ведётся без них с первого коммита.
6d. **Перед любым `git reset --soft HEAD~N` смотреть, чей коммит на верхушке, и не трогать опубликованное** (инцидент 2026-08-02, дважды за один заход). Пока я переписывал своё сообщение, параллельная сессия закоммитила поверх; `reset --soft HEAD~1` вернул её коммит в staged-файлы, она закоммитила заново — я снёс второй раз. Восстановлено `git commit -C <потерянный хеш>` (сообщение, автор и дата сохраняются), содержимое сверено `git diff <потерянный> HEAD`. Два правила: (1) непосредственно перед сбросом — `git log -1 --format='%h %s'`, чужая верхушка = сброс запрещён; (2) `git status -sb` — если коммит уже ушёл на origin, переписывать его нельзя вовсе, чинится только новым коммитом поверх, иначе ветка расходится с origin и требует форс-пуша. Вывод: правку своего сообщения или состава делать **сразу после коммита и до любой паузы**, а лучше — вычитывать до коммита.
