Ключевое из этапа 0 (подробности — отчёт `spike-report.md`):

- **Версии зафиксированы:** three 0.185.1, TypeScript 7.0.2, esbuild 0.28.1, Playwright 1.62.0, Node 24.15.0, системный Chrome 150.0.7871.182 (`channel: 'chrome'`), pngjs 7.0.0 + pixelmatch 7.2.0.
- **Эталонный контур = SwiftShader + флаги** `--use-angle=swiftshader --enable-unsafe-swiftshader`; без них headless-Chrome уходит на реальный GPU и кадр расходится (104 пикселя, макс. отклонение 189). Счётчики идентичны — слой 1 от видеокарты не зависит, слой 2 зависит. Ограничения: `MAX_TEXTURE_SIZE` 8192, `MAX_SAMPLES` 4.
- **Детерминированность полная:** кадр 640×360 побайтово идентичен между прогонами и после перезапуска, если кадр — функция своего номера.
- **Кадры сверять по пикселям, не по хешу файла.**
- **Ловушка контекста:** повторный `getContext` возвращает уже созданный контекст и молча теряет атрибуты — пробник WebGL 2 опрашивать на отдельном холсте.
- **Ассеты в Node без GPU:** GLB разбирается `GLTFLoader.parse()` без заглушек; `GLTFExporter` требует полифилл `FileReader.readAsArrayBuffer`; текстуры требуют `self`, `ProgressEvent`, `createImageBitmap`, а для GLB — реестр `blob:`-адресов с подменой `fetch` и обрезку добивки после `IEND`.
- **Стабильны только счётчики объектов**, байты памяти гуляют, время прогона ≈32 % — абсолютные тайминги в критерии приёмки не входят.
- **Приём:** ступенчатые опыты с заглушками гонять каждый в своём процессе (`FileLoader` склеивает одинаковые адреса и даёт ложные «зависания»).
