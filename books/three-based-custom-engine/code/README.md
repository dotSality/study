# code/ — проверяемые состояния движка

Один проект, одна установка зависимостей, а состояний движка столько, сколько написано глав: каждая глава оставляет каталог с тем кодом, на котором она проверялась.

```
code/
├── package.json  tsconfig.json    один проект на всю книгу; node_modules не коммитится
├── chapters/NN-<slug>/            состояние движка на конец главы NN
│   ├── src/main.ts  src/engine/   движок и точка входа страницы
│   ├── tests/*.test.mjs           слой 3: проверки без браузера
│   ├── harness/*.mjs              стенд: сборка, сервер, сценарии слоя 2
│   └── web/index.html             страница этого состояния
├── shell/                         оболочка: сборка всех состояний и шапка-переключатель
└── web/                           собранная страница со всеми состояниями (не коммитится)
```

Каталог главы — точная копия проекта, который к этому моменту собрал у себя читатель: те же имена файлов, те же команды, тот же `harness/build.mjs`, что напечатан в книге. Единственное отличие — `package.json` и `tsconfig.json` живут этажом выше, общие на все главы.

**Команды** (из корня `code/`):

```
npm install        точные версии зависимостей, без диапазонов
npm run typecheck  tsc --noEmit по всем состояниям сразу
npm run build      собрать страницу-стенд со всеми состояниями
npm run dev        собрать и поднять её на http://127.0.0.1:5173/
npm test           прогнать проверки всех глав: в каждом каталоге свой `node --test`
```

Одна глава прогоняется отдельно так: `cd chapters/02-frame-loop && node --test`.

**Зачем это в репозитории.** Правило 5.4 книги требует, чтобы каждый листинг был непрерывным фрагментом реально работающего файла, а каждое число в тексте (счётчики `renderer.info`, вывод прогонов, поведение браузера) было снято прогоном. Состояния глав — то, на чём это проверено. Заодно тесты старых глав остаются в строю: правка в главе 12 не может незаметно сломать то, что обещано в главе 2.

**Граница, которая не нарушается.** В каталог главы попадает ровно то, что напечатано в самой главе: разобранные примеры, тесты и стенд. **Реализаций заданий здесь нет и не будет** — они пишутся на этапе 5 в `solutions/NN-<slug>.md`, прогоняются в одноразовом каталоге и в состояния глав не вливаются. Движок читателя — его собственный проект; свобода имён обеспечена адаптером соответствия (решение Р1.4).

**Снимки контрольных точек** (`engine/checkpoint-NN/` в корне книги, главы 5, 9, 13, 18, 22) остаются как были: они собирают состояние блока целиком и приезжают с эталонными кадрами.

Не коммитятся: `node_modules/`, `web/` в корне, `chapters/*/web/bundle.js*`, `chapters/*/harness/out/`.
