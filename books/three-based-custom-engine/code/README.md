# code/ — рабочий проект книги

Здесь живёт код, на котором пишется книга: тот самый, который цитируется главами листингами и на котором сняты все их числа — счётчики `renderer.info`, вывод прогонов, поведение браузера.

**Каталог в репозиторий не попадает** (решение владельца 2026-08-13, вечернее; отменяет утреннее решение того же дня). Довод владельца: это артефакт **написания** книги, а не артефакт книги, и в гите ему делать нечего. Отслеживается один файл — этот README. При этом каталог **не очищается**: он остаётся на машине между заходами, и восстанавливать его в начале каждого захода не нужно — отменена отслеживаемость, а не сам каталог.

**Роль у этого кода одна: быть опорой для написания теории.** Он не артефакт книги и не то, что читатель получает в руки: читатель собирает движок сам, по листингам глав и заданиям. Поэтому к нему не предъявляется требований полноты, красоты API или обратной совместимости — от него нужно, чтобы на нём можно было проверить каждое утверждение главы и снять каждое её число.

Артефакты книги — другое: снимки контрольных точек `engine/checkpoint-NN/` (документированные состояния движка, пригодные к запуску) и стенд `harness/`. Их правила не меняются.

## Устройство: один проект на всю книгу

Одни зависимости, один `node_modules`, один `tsconfig.json`, один `npm test` на все главы разом. Артефакты глав разводятся **страницами и подмодулями**, а не отдельными проектами.

```
package.json, tsconfig.json    одни зависимости и одна проверка типов на всё
src/engine/*.ts                ядро движка: растёт от главы к главе
src/assets/*.ts                слой над ядром: форматы и источник байтов (гл. 6–7)
src/render/*.ts                мост к three.js
src/main.ts                    точка входа страницы 1 — сцена КТ1 (гл. 1–5)
src/assets-main.ts             точка входа страницы 2 — конвейер ресурсов (гл. 6–7)
web/index.html, web/assets.html   страницы стенда, по одной на точку входа
web/assets/                    файлы ассетов стенда
tests/*.test.mjs               слой 3: без графического контекста
harness/                       слой 2, сервер, сборка, генераторы ассетов
```

Новая глава добавляет модули в `src/` и, если ей нужен свой стенд, новую страницу: точка входа `src/<тема>-main.ts`, `web/<тема>.html` и запись в `harness/build.mjs`. **Вложенный `package.json`, второй `node_modules` и каталог на главу запрещены** — схема `code/chapters/NN-<slug>/` уже пробовалась и отменена 2026-07-30: одну и ту же правку приходилось вносить в каждую копию.

## Чем это грозит и как воссоздать каталог

Каталога нет в гите — значит он живёт до первого `git clean -xdf`, до новой машины и до отказа диска. Цена потери названа точно, потому что её уже платили: восстановление кода по листингам выполнялось **пять раз подряд**, в последний раз — сразу за две главы, около 2500 строк. Так же — потерей кода, лежавшего в отменённых каталогах, — главы 1–4 стали «неподвижными»: их листинги больше не с чем сверять, и решением 2026-08-13 сверка их прекращена совсем.

Порядок восстановления, если каталог всё-таки исчез:

1. Развернуть последний снимок контрольной точки: `cp -r engine/checkpoint-01/. code/`, затем вернуть этот README из гита — снимок его перезаписывает. Это состояние после главы 5, прогон — 173 теста.
2. Набрать поверх код глав 6 и 7 по их листингам. После главы 6 прогон обязан давать **273** теста, после главы 7 — **296**.
3. Доказательство верности восстановления — механическое: `harness/verify-chapter.mjs` требует, чтобы каждый листинг был дословным непрерывным фрагментом реального файла. Ноль проблем плюс зелёные тесты плюс чистый `tsc` означают, что восстановленный код совпадает с тем, по которому написана глава.

**Чем полнее листинги, тем дешевле эта операция**, и здесь у решения есть срок годности: проверка «показанное опирается только на показанное» (правило 10 раздела 5) доведена до нуля в главе 7, но в главах 5 и 6 остаются 12 и 21 непоказанное имя. Пока этот долг не закрыт, восстановление глав 5–6 по тексту потребует догадок — то есть ровно того, что запрещено. После его закрытия риск становится обычной ценой удобства.

## Почему решение менялось дважды за день

До утра 2026-08-13 действовало правило очистки: каталог стирался в конце захода, а точкой входа в следующий служило восстановление по листингам. Оно исходило из того, что текст глав самодостаточен. Условие оказалось неверным: глава 7 вышла с листингами, которых читателю не хватает (151 строка кода в тексте против 542 в главе 6), и очистка превратила текстовый дефект в переписывание двух глав кода. Утреннее решение сняло эту цену хранением каталога в гите; вечернее вернуло каталог из гита на машину, оставив отменённой только очистку. Итог: **код хранится, но не коммитится**.

Ни одно из трёх решений не ослабляет требования к листингам: текст главы обязан содержать достаточно кода, чтобы читатель собрал своё, и это проверяется отдельно — `harness/verify-chapter.mjs`, критерии достаточности и опоры.

## Как проверяется глава

```
node harness/verify-chapter.mjs <номер главы> <файл главы> code
```

Скрипт проверяет три вещи: **подлинность** — каждый листинг является дословным непрерывным фрагментом реального файла проекта; **достаточность** — доля кода главы, попавшая в текст, законченные единицы в каждой части и их доля среди листингов; **опору** — каждое имя, на которое ссылается листинг и которое объявлено верхним уровнем того же файла, показано объявлением в этой главе или в предыдущих.

Код возврата различает два разных исхода: **1** — у главы есть проблемы, **2** — рабочего проекта нет на месте и сверять не с чем.

**Сам скрипт в гите тоже не лежит** (решение владельца 2026-08-13, тем же доводом, что и про этот каталог: инструмент автора, не артефакт книги). Он остаётся на своём месте, `books/three-based-custom-engine/harness/verify-chapter.mjs`, но под наблюдение не берётся. Восстанавливать его не из чего — это метод, а не состояние, — поэтому единственный запасной путь: `git show fe94d62:books/three-based-custom-engine/harness/verify-chapter.mjs`, где он лежит последний раз отслеженным. В `harness/` под наблюдением остаётся только то, что артефактом книги является: эталонный кадр и его паспорт.

## Что здесь не появляется никогда

Реализации заданий. Они пишутся на этапе 5 в `solutions/NN-<slug>.md` и прогоняются в одноразовом каталоге. Иначе «рабочий проект» незаметно превратится в сборник ответов.

## Команды

```
npm install        # зависимости
npm test           # весь прогон, слои 2 и 3; ассеты главы 7 собираются сами (pretest)
npm run typecheck  # tsc --noEmit
npm run dev        # стенд на 127.0.0.1:5173 (обе страницы)
npm run assets     # только пересобрать тестовые ассеты главы 7
```

С чистого клона хватает двух первых команд: тестовые ассеты `*.glb` не коммитятся (правило 5.9 — генерируются скриптом), и `pretest` собирает их перед каждым прогоном. Проверено удалением файлов и прогоном.

**Сверка главы требует установленных зависимостей:** листинг §6.2.4 цитирует `GLTFLoader.js` из `node_modules/three`, и без него скрипт сообщит о ненайденном листинге.
