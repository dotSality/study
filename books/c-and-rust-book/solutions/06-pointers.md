## Часть 6.1. Адреса и указатели

### Г6.Ч1.З1

**Условие.** Объявите `int x = 25;` и указатель `int *p = &x;`. Напечатайте: значение `x`, значение `*p`, адрес `&x` (через `%p`, приведя к `(void*)`) и `sizeof(p)`. Убедитесь, что `x` и `*p` равны.

**Решение.** `p` инициализирован адресом `x`, поэтому разыменование `*p` читает ту же самую ячейку, что и имя `x`, — значения обязаны совпасть. Адрес печатается спецификатором `%p` с приведением аргумента к `(void*)` (§6.1.1). `sizeof(p)` — размер самого указателя: на нашей 64-битной платформе адрес занимает 8 байт независимо от типа указуемого объекта.

```c
#include <stdio.h>

int main(void)
{
    int x = 25;
    int *p = &x;                      // p хранит адрес x
    printf("x  = %d\n", x);
    printf("*p = %d\n", *p);          // значение по адресу p — это x
    printf("&x = %p\n", (void*)&x);   // адрес печатают %p через (void*)
    printf("sizeof(p) = %zu\n", sizeof(p));
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra ptrbasics.c -o ptrbasics
./ptrbasics
```

```
x  = 25
*p = 25
&x = 0000009bc75ff9f4
sizeof(p) = 8
```

`x` и `*p` дали одинаковые `25` — это одна ячейка, прочитанная двумя способами. Конкретное число адреса (`...f9f4`) — своё при каждом запуске; постоянен только его размер.

**Ответ:** `x = 25` и `*p = 25` совпадают (одна и та же ячейка); адрес `&x` — непостоянное число вида `0000009bc75ff9f4`; `sizeof(p) = 8`.

### Г6.Ч1.З2

**Условие.** Даны `int x = 7;` и `int *p = &x;`. Измените `x` **через указатель** (`*p = 100;`) и напечатайте `x`. Затем измените `x` напрямую (`x = 1;`) и напечатайте `*p`. Объясните в комментарии, почему в обоих случаях второе значение «догоняет» первое.

**Решение.** У ячейки `x` два «входа»: имя `x` и разыменование `*p`. Оба ведут к одной и той же памяти, поэтому запись через любой из них немедленно видна через другой — никакой копии здесь нет.

```c
#include <stdio.h>

int main(void)
{
    int x = 7;
    int *p = &x;                  // p и имя x ведут к одной ячейке
    *p = 100;                     // пишем в ячейку через указатель
    printf("x  = %d\n", x);       // 100 — имя x читает ту же ячейку
    x = 1;                        // пишем в ячейку напрямую
    printf("*p = %d\n", *p);      // 1 — *p читает ту же ячейку
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra twoway.c -o twoway
./twoway
```

```
x  = 100
*p = 1
```

**Ответ:** печатается `100`, затем `1`. «Догоняние» — иллюзия: `x` и `*p` — не две переменные, а два имени одной ячейки, поэтому любое изменение сразу «видно» обоим.

### Г6.Ч1.З3

**Условие.** Объявите два `int` (`a = 3`, `b = 9`) и один указатель `int *p`. Направьте `p` сначала на `a`, напечатайте `*p`; затем на `b`, напечатайте `*p`. Выведите также результат сравнения `p == &b` (ожидается `1`).

**Решение.** Указатель — обычная переменная: хранимый в ней адрес можно заменить. После `p = &b` то же выражение `*p` читает уже другую ячейку. Сравнение `p == &b` истинно, потому что в `p` лежит именно адрес `b`.

```c
#include <stdio.h>

int main(void)
{
    int a = 3, b = 9;
    int *p = &a;                  // p -> a
    printf("*p = %d\n", *p);
    p = &b;                       // перенаправили: p -> b
    printf("*p = %d\n", *p);
    printf("p == &b: %d\n", p == &b);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra retarget.c -o retarget
./retarget
```

```
*p = 3
*p = 9
p == &b: 1
```

**Ответ:** `3`, затем `9`, затем `1`. Один и тот же `*p` даёт разные значения, потому что между печатями изменился адрес, хранящийся в `p`.

### Г6.Ч1.З4

**Условие.** *(понимание)* Не запуская, предскажите вывод и объясните каждую строку:

```c
int x = 4;
int *p = &x;
*p = *p + 10;
printf("%d %d\n", x, *p);
```

**Решение.** Разбираем построчно:

1. `int x = 4;` — ячейка `x` со значением `4`.
2. `int *p = &x;` — `p` хранит адрес `x`; теперь `*p` — второй вход в ту же ячейку.
3. `*p = *p + 10;` — справа `*p` **читает** ячейку (`4`), прибавляется `10`; слева `*p =` **записывает** `14` обратно в ту же ячейку. Значит, `x` стал `14`.
4. `printf` печатает `x` и `*p` — а это одна ячейка, обе печати дадут `14`.

Проверка запуском:

```c
#include <stdio.h>

int main(void)
{
    int x = 4;
    int *p = &x;
    *p = *p + 10;                 // прочитали 4, записали 14 — в саму x
    printf("%d %d\n", x, *p);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra predict14.c -o predict14
./predict14
```

```
14 14
```

**Ответ:** `14 14`. Строка `*p = *p + 10;` читает и пишет саму `x` (косвенный доступ), после чего оба выражения — `x` и `*p` — читают одно и то же обновлённое значение.

### Г6.Ч1.З5

**Условие.** *(понимание)* Найдите ошибку и объясните, к чему она приведёт при запуске (не запускайте):

```c
int *p;          // не инициализирован
*p = 42;
printf("%d\n", *p);
```

Как исправить, если цель — «завести переменную и записать в неё 42 через указатель»?

**Решение.** Ошибка — в первой же паре строк: `p` объявлен, но не инициализирован, значит, содержит **мусорный адрес** (как любая неинициализированная переменная, §4.2.1). Строка `*p = 42;` записывает `42` по этому случайному адресу — это неопределённое поведение (глава 13): программа может упасть сразу, а может молча испортить чужие данные и «работать» — второй исход хуже, потому что ошибка всплывёт далеко от места причины.

Мы собрали эту программу эталонной командой (**не** запуская): компилятор сам видит беду и предупреждает —

```
uninit_ub.c: In function 'main':
uninit_ub.c:6:8: warning: 'p' is used uninitialized [-Wuninitialized]
    6 |     *p = 42;                      // запись по мусорному адресу
      |     ~~~^~~~
uninit_ub.c:5:10: note: 'p' was declared here
    5 |     int *p;                       // не инициализирован: внутри мусорный адрес
      |          ^
```

Вывод программы не приводим: у неопределённого поведения гарантированного вывода не существует. Исправление: указателю нужна **настоящая ячейка** — заводим переменную и направляем `p` на неё:

```c
#include <stdio.h>

int main(void)
{
    int x;                        // настоящая ячейка под число
    int *p = &x;                  // p указывает на существующую переменную
    *p = 42;                      // запись уходит в x
    printf("%d\n", *p);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra uninit_fix.c -o uninit_fix
./uninit_fix
```

```
42
```

**Ответ:** ошибка — разыменование неинициализированного указателя: запись по мусорному адресу, неопределённое поведение (крах или тихая порча памяти). Исправление — сначала дать `p` адрес существующей переменной (`int x; int *p = &x;`), и только потом писать `*p = 42;` — программа печатает `42`. Эталонная сборка, к слову, ловит эту ошибку предупреждением `-Wuninitialized`.

### Г6.Ч1.З6

**Условие.** *(понимание)* Дан код. Что напечатается и почему изменения `set_zero` **не видны** в `main`? Как исправить, чтобы `x` стал `0`?

```c
#include <stdio.h>

void set_zero(int *p) { p = 0; }     // обратите внимание: p, а не *p
int main(void) {
    int x = 5;
    set_zero(&x);
    printf("%d\n", x);
    return 0;
}
```

**Решение.** Параметр `p` — **копия** переданного адреса (параметры всегда передаются по значению, §4.1.3 — в том числе и указатели). Строка `p = 0;` перезаписывает эту копию нулём (делает её нулевым указателем) — к ячейке `x` функция даже не прикоснулась. Копия исчезает вместе с функцией, `x` остаётся `5`.

Эталонная сборка прямо намекает на бессмысленность происходящего:

```
setzero_wrong.c: In function 'set_zero':
setzero_wrong.c:3:20: warning: parameter 'p' set but not used [-Wunused-but-set-parameter]
    3 | void set_zero(int *p) { p = 0; }     // обнуляется КОПИЯ указателя, не x
      |               ~~~~~^
```

— «параметру присвоили, но так и не использовали». Запуск подтверждает:

```
5
```

Исправление — **разыменовать**: `*p = 0;` пишет не в копию адреса, а в ячейку по этому адресу, то есть в `x`:

```c
#include <stdio.h>

void set_zero(int *p) { *p = 0; }    // разыменование: пишем в ячейку вызывающего

int main(void)
{
    int x = 5;
    set_zero(&x);
    printf("%d\n", x);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra setzero_fix.c -o setzero_fix
./setzero_fix
```

```
0
```

**Ответ:** напечатается `5`: `p = 0;` обнуляет локальную копию указателя, а не `x`. Исправление — `*p = 0;` (разыменование): тогда печатается `0`. Правило: `p` — сам адрес (копия), `*p` — ячейка вызывающего.

### Г6.Ч1.З7

**Условие.** *(понимание)* Объясните, почему `scanf("%d", &n)` требует `&`, а `scanf("%9s", name)` (для `char name[10]`) — нет. Свяжите ответ с механизмом выходного параметра (§6.1.3) и распадом имени массива (анонс §6.2.1).

**Решение.** `scanf` — функция с **выходными параметрами**: прочитанное она должна записать в переменные вызывающего, а для записи ей нужны их **адреса** (§6.1.3). Отсюда две ситуации:

- `n` — обычный `int`. Выражение `n` — это *значение* (копия числа); записать по копии некуда. Поэтому адрес берут явно: `&n`.
- `name` — **массив** `char name[10]`. Имя массива в выражении само **распадается** в адрес первого элемента (§6.2.1): `name` — это уже `&name[0]`. Адрес готов — оператор `&` не нужен.

То есть `&` нужен не «числам» и не нужен «строкам» по какой-то особой договорённости — правило одно: `scanf` всегда получает адрес; у скаляра его берут оператором `&`, у массива он получается сам, распадом имени.

Проверка запуском (ввод подан конвейером `printf '42 pointer\n' | ./scanfdemo`):

```c
#include <stdio.h>

int main(void)
{
    int n;
    char name[10];
    scanf("%d", &n);              // числу нужен явный адрес: &n
    scanf("%9s", name);           // имя массива — уже адрес name[0]
    printf("n = %d, name = %s\n", n, name);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra scanfdemo.c -o scanfdemo
printf '42 pointer\n' | ./scanfdemo
```

```
n = 42, name = pointer
```

**Ответ:** `scanf` пишет результат по адресу (механизм выходного параметра), поэтому ей всегда передают адрес. Для скаляра `n` адрес берут явно (`&n`); имя массива `name` в выражении уже распалось в адрес первого элемента, и `&` не нужен — обе записи передают адрес, просто получен он по-разному.

### Г6.Ч1.З8

**Условие.** *(прикладное)* Напишите функцию `void add_ten(int *p)`, которая прибавляет `10` к переменной по адресу `p`. В `main` примените её к `int v = 5;` (через `add_ten(&v)`) и напечатайте `v` (ожидается `15`).

**Решение.** Классический «возврат через аргумент» (§6.1.3): функция получает адрес `v`, читает значение через `*p`, прибавляет `10` и записывает обратно — в саму переменную вызывающего.

```c
#include <stdio.h>

void add_ten(int *p)
{
    *p = *p + 10;                 // меняем переменную вызывающего по адресу
}

int main(void)
{
    int v = 5;
    add_ten(&v);                  // передаём АДРЕС v
    printf("v = %d\n", v);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra addten.c -o addten
./addten
```

```
v = 15
```

**Ответ:** `v = 15`. Функция изменила переменную `main` на месте — через переданный адрес и разыменование.

**Вариант 2 (возврат значением).** Ту же задачу «прибавить 10 к `v`» решает обычная функция из главы 4 — без указателей, но с обязательным присваиванием результата у вызывающего:

```c
#include <stdio.h>

int add_ten(int v)                // получает копию, отдаёт новое значение
{
    return v + 10;
}

int main(void)
{
    int v = 5;
    v = add_ten(v);               // результат нужно присвоить самому
    printf("v = %d\n", v);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra addten_ret.c -o addten_ret
./addten_ret
```

```
v = 15
```

*Сравнение.* Результат одинаков, различается ответственность: указательная версия меняет `v` сама (вызвал — и переменная уже новая), return-версия лишь вычисляет значение, а обновление (`v = add_ten(v)`) — забота вызывающего, и его легко забыть. Для одного результата return-версия проще и прозрачнее (нет `&`/`*`); указательная незаменима, когда результатов несколько (Г6.Ч1.З10) или когда семантика — именно «изменить объект на месте».

### Г6.Ч1.З9

**Условие.** *(прикладное)* Напишите функцию `void swap(int *a, int *b)`, меняющую местами два `int` через указатели. Проверьте на `x = 10, y = 20`: после `swap(&x, &y)` должно быть `20 10`. Сравните в комментарии с тем, почему версия из §4.1.3 (`swap(int a, int b)`) не работала.

**Решение.** Обмен через временную переменную, но все чтения и записи — по адресам: `*a` и `*b` — это сами `x` и `y` вызывающего, поэтому перестановка видна снаружи.

```c
#include <stdio.h>

void swap(int *a, int *b)         // принимаем АДРЕСА двух переменных
{
    int t = *a;                   // спасаем значение первой
    *a = *b;                      // в первую кладём вторую
    *b = t;                       // во вторую — старое значение первой
}

int main(void)
{
    int x = 10, y = 20;
    swap(&x, &y);
    printf("%d %d\n", x, y);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra swapptr.c -o swapptr
./swapptr
```

```
20 10
```

**Ответ:** `20 10` — обмен состоялся. Версия §4.1.3 не работала, потому что получала *копии* значений и переставляла их внутри себя; эта версия получает *адреса* и переставляет содержимое самих ячеек `x` и `y`.

**Типичная неверная попытка.** Та самая версия из §4.1.3 — передача по значению:

```c
void swap(int a, int b)           // копии (§4.1.3): обмен не виден снаружи
{
    int t = a;
    a = b;
    b = t;
}
...
swap(x, y);                       // переданы ЗНАЧЕНИЯ, не адреса
```

```
10 20
```

Программа компилируется чисто и «работает» — но переставляет лишь копии, живущие внутри функции; `x` и `y` остаются нетронутыми (вывод выше — реальный прогон такой версии). Внешне разница с рабочим `swap` — лишь `*` в параметрах и `&` в вызове; по сути — пропасть: значения против адресов.

### Г6.Ч1.З10

**Условие.** *(прикладное)* Напишите функцию `void div_rem(int a, int b, int *q, int *r)`, возвращающую **через выходные параметры** частное и остаток от деления `a` на `b`. Проверьте на `a = 23, b = 4` (ожидается `q = 5, r = 3`) и `a = 100, b = 10` (ожидается `q = 10, r = 0`).

**Решение.** Входные данные (`a`, `b`) идут по значению, оба результата — по адресам: `*q` и `*r` — это переменные `q` и `r` вызывающего. Обычный `return` вернул бы одно число, выходные параметры возвращают оба сразу (§6.1.3).

```c
#include <stdio.h>

void div_rem(int a, int b, int *q, int *r)
{
    *q = a / b;                   // частное — в ячейку вызывающего
    *r = a % b;                   // остаток — во вторую ячейку
}

int main(void)
{
    int q, r;
    div_rem(23, 4, &q, &r);       // передаём адреса обеих ячеек
    printf("23 / 4:   q = %d, r = %d\n", q, r);
    div_rem(100, 10, &q, &r);
    printf("100 / 10: q = %d, r = %d\n", q, r);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra divrem.c -o divrem
./divrem
```

```
23 / 4:   q = 5, r = 3
100 / 10: q = 10, r = 0
```

**Ответ:** `q = 5, r = 3` и `q = 10, r = 0` — оба контрольных случая сошлись; функция вернула по два значения за вызов.

**Типичная неверная попытка.** Забыть `&` при вызове: `div_rem(23, 4, q, r);`. Современный GCC такое уже **не пропускает** — несовпадение типов (`int` вместо `int *`) стало ошибкой компиляции, причём компилятор сам подсказывает исправление:

### Г6.Ч2.З2

**Условие.** Дан `int a[5] = {2, 4, 6, 8, 10};` и `int *p = a;`. Напечатайте `*p`, `*(p + 2)`, `*(p + 4)`. Затем выполните `p += 2;` и напечатайте `*p`. Объясните в комментарии, на какой элемент теперь указывает `p`.

**Решение.** `p` стартует на `a[0]`. Прибавление к указателю считается **в элементах** (§6.2.2): `p + 2` — адрес `a[2]`, `p + 4` — адрес `a[4]`. Выражения `*(p + k)` сам `p` не меняют; а вот `p += 2;` сдвигает сам указатель — теперь он хранит адрес `a[2]`, и `*p` читает шестёрку.

```c
    printf("after p += 2: *p = %d\n", *p);
    return 0;
}
```

### Г6.Ч2.З5

**Условие.** *(понимание)* Дан массив `int a[3]` и указатели `int *p = &a[0], *q = &a[2];`. Чему равно `q - p`? А `(char*)q - (char*)p` (на нашей платформе)? Объясните, почему эти числа различаются и во сколько раз.

**Решение.** Разность указателей считается **в элементах того типа, на который они указывают** (§6.2.2). Между `a[0]` и `a[2]` — два `int`-элемента, поэтому `q - p == 2`.     printf("(char*)q - (char*)p = %td\n", (char*)q - (char*)p);   // в байтах
```c
    return 0;
}
```

**Ответ:** `q - p = 2` (элемента), `(char*)q - (char*)p = 8` (байт) — на нашей платформе. Различие в `sizeof(int) = 4` раза: арифметика указателей автоматически учитывает размер типа, а `char *` со своим шагом в 1 байт «показывает» расстояние в байтах.

**Условие.** *(понимание)* Объясните, почему `sizeof a` внутри функции `void f(int a[])` даёт `8`, а не размер массива вызывающего. На что «на самом деле» указывает `a`? Свяжите с тем, почему функции нужна отдельная длина (§5.1.4, §6.2.1).

Проверьте на изменяемом массиве `char t[] = "Hello, World";` (ожидается `HELLO, WORLD`). Почему аргумент нельзя объявлять `const char *`?

**Решение.** Обходим строку самим параметром `s` (он — копия адреса, двигать его безопасно). Строчные латинские буквы занимают в таблице символов сплошной диапазон `'a'…'z'`; проверка попадания и сдвиг `*s - ('a' - 'A')` переводят букву в заглавный диапазон, прочие символы (запятая, пробел, уже заглавные) не трогаем. Запись `*s = ...` идёт в массив вызывающего — перевод происходит «на месте».

```c
#include <stdio.h>

void to_upper(char *s)                // не const: функция ПИШЕТ в строку
{
    while (*s != '\0') {
        if (*s >= 'a' && *s <= 'z')   // строчная латинская буква?
            *s = *s - ('a' - 'A');    // сдвигаем в заглавный диапазон
        s++;                          // двигаем копию указателя
    }
}

int main(void)
{
    char t[] = "Hello, World";        // изменяемый массив, не литерал
    to_upper(t);
    printf("%s\n", t);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra touppercase.c -o touppercase
./touppercase
```

```
HELLO, WORLD
```

Почему не `const char *`? Потому что `const` — контракт «только чтение» (§6.3.1), а `to_upper` строку **изменяет**. Мы собрали версию с `const char *s` — компилятор отверг её ровно на строке записи:

```
toupper_const.c: In function 'to_upper':
toupper_const.c:7:16: error: assignment of read-only location '*s'
    7 |             *s = *s - ('a' - 'A');    // попытка записи через const-указатель
      |                ^
```

**Ответ:** `HELLO, WORLD`. Аргумент нельзя объявлять `const char *`, потому что функция пишет в строку (`*s = ...`), а запись через указатель на `const` — ошибка компиляции (`assignment of read-only location '*s'`): `const` в сигнатуре обещал бы «только читаю» — и этот контракт здесь заведомо нарушен.

**Вариант 2 (индексный обход).** Та же логика без движения указателя — индексом `i` по `s[i]`:

```c
#include <stdio.h>

void to_upper(char *s)
{
    for (size_t i = 0; s[i] != '\0'; i++)   // индексный обход той же строки
        if (s[i] >= 'a' && s[i] <= 'z')
            s[i] = s[i] - ('a' - 'A');
}

int main(void)
{
    char t[] = "Hello, World";
    to_upper(t);
    printf("%s\n", t);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra toupper_idx.c -o toupper_idx
./toupper_idx
```

```
HELLO, WORLD
```

*Сравнение.* Указательная версия следует условию и идиоме §6.2.3 (двигаем `s`, читаем-пишем `*s`); индексная сохраняет неподвижным начало строки — это удобно, если адрес начала ещё понадобится (например, чтобы в конце напечатать строку из той же функции). Внутри обе — одно и то же: `s[i]` есть `*(s + i)`.

### Г6.Ч3.З1

**Условие.** Объявите `int x = 42;` и `const int *p = &x;`. Напечатайте `*p`. Затем измените `x` **напрямую** (`x = 99;`) и снова напечатайте `*p`. Объясните в комментарии, почему запись `*p = 99;` не скомпилировалась бы, а `x = 99;` — можно.

**Решение.** `const int *p` — «указатель на const int»: **через `p`** значение менять нельзя, но сам объект `x` от этого `const`-ом не становится (§6.3.1). `const` ограничивает *путь доступа*, а не ячейку: прямое присваивание `x = 99;` законно, и `p`, глядя на ту же ячейку, видит новое значение.

```c
#include <stdio.h>

int main(void)
{
    int x = 42;
    const int *p = &x;            // «взгляд только для чтения» на x
    printf("*p = %d\n", *p);
    x = 99;                       // сам x не const: прямая запись законна
    printf("*p = %d\n", *p);      // p видит новое значение той же ячейки
    return 0;
}
```

```

    5 |     *p = 99;            // запись через указатель на const

```

**Ответ:** печатается `42`, затем `99`. `*p = 99;` не скомпилировалась бы (`assignment of read-only location '*p'`) — тип `const int *` запрещает запись *через этот указатель*; `x = 99;` можно — сама переменная `x` не `const`, запрет касается только пути доступа через `p`.

### Г6.Ч3.З2

**Условие.** Объявите `int x = 5;`, `int *p = &x;`, `int **pp = &p;`. Напечатайте `x`, `*p`, `**pp` (все три равны `5`). Затем выполните `**pp = 50;` и напечатайте `x` (ожидается `50`).

**Решение.** Цепочка из двух звеньев: `pp` хранит адрес `p`, `p` — адрес `x`. Одно разыменование `*pp` даёт `p` (адрес `x`), второе — `**pp` — саму `x`. Запись `**pp = 50;` проходит по обеим стрелкам и меняет `x`.

```c
#include <stdio.h>

int main(void)
{
    int x = 5;
    int *p = &x;                  // p -> x
    int **pp = &p;                // pp -> p
    printf("x = %d, *p = %d, **pp = %d\n", x, *p, **pp);
    **pp = 50;                    // два прыжка: pp -> p -> x
    printf("x = %d\n", x);
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra doubleptr.c -o doubleptr
./doubleptr
```

```

x = 50
```

**Ответ:** сначала `x = 5, *p = 5, **pp = 5` (три дороги к одной ячейке), после `**pp = 50;` — `x = 50`. Каждая звёздочка — один прыжок по адресу.

**Типичная неверная попытка.** Недобрать звёздочку: `*pp = 50;` — намерение «записать 50 в `x`», а по типам это запись числа в **сам указатель** `p`. Современный GCC такое не пропускает — типы не совпали (`int *` слева, `int` справа), ошибка компиляции:

```

doubleptr_onestar.c:8:9: error: assignment to 'int *' from 'int' makes pointer from integer without a cast [-Wint-conversion]
    8 |     *pp = 50;                     // недобор звёздочки: пишем в САМ указатель p
      |         ^
```

Считайте прыжки: `*pp` — это `int *` (адрес), `**pp` — `int` (значение). Система типов здесь — страховка: перепутали уровень — получили отказ компиляции, а не мусорный адрес в `p`.

### Г6.Ч3.З3

**Условие.** Объявите функции `int mul(int a, int b)` и `int sub(int a, int b)`. Заведите указатель `int (*op)(int, int)`, направьте его сначала на `mul`, напечатайте `op(6, 7)` (ожидается `42`); затем на `sub`, напечатайте `op(6, 7)` (ожидается `-1`).

**Решение.** `int (*op)(int, int)` — указатель на функцию с сигнатурой «два `int` → `int`» (скобки вокруг `*op` обязательны, §6.3.3). Имя функции распадается в её адрес, поэтому `op = mul;` заряжает указатель, а `op(6, 7)` вызывает текущую функцию.

```c
#include <stdio.h>

int mul(int a, int b) { return a * b; }
int sub(int a, int b) { return a - b; }

int main(void)
{
    int (*op)(int, int) = mul;    // op хранит адрес mul
    printf("op(6, 7) = %d\n", op(6, 7));
    op = sub;                     // перенаправили на sub
    printf("op(6, 7) = %d\n", op(6, 7));
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra fptr.c -o fptr
./fptr
```

```

op(6, 7) = -1
```

**Ответ:** `42`, затем `-1`. Один и тот же вызов `op(6, 7)` исполняет разные функции — по текущему адресу в указателе: «поведение как данные».

**Вариант 2 (таблица из массива указателей).** Обе функции можно сложить в **массив указателей на функции** и выбирать действие индексом — зачаток таблицы диспетчеризации (§6.3.3, «Связь с практикой»):

```c
#include <stdio.h>

int mul(int a, int b) { return a * b; }
int sub(int a, int b) { return a - b; }

int main(void)
{
    int (*ops[2])(int, int) = {mul, sub};   // массив указателей на функции
    for (int i = 0; i < 2; i++)             // выбор действия — по индексу
        printf("ops[%d](6, 7) = %d\n", i, ops[i](6, 7));
    return 0;
}
```

Синтаксис объявления массива (`int (*ops[2])(int, int)`) громоздок, но строится из уже знакомых частей: «массив из 2 указателей на функцию (int, int) → int».

### Г6.Ч3.З4

**Условие.** *(понимание)* Для каждого объявления скажите, что именно нельзя менять (значение, сам указатель или оба), и приведите строку, которая не скомпилируется:

```c
const int *p;
int *const q;
const int *const r;
```

(указатели считать инициализированными на некий `int x`.)

**Решение.** Читаем справа налево (§6.3.1):

- `const int *p` — указатель на **const int**: заморожено *значение* (нельзя `*p = ...`), сам `p` свободен (`p = &y;` — можно). Не скомпилируется: `*p = 5;`
- `int *const q` — **const-указатель** на int: заморожен *сам указатель* (нельзя `q = ...`), значение через него менять можно (`*q = 5;` — можно). Не скомпилируется: `q = &y;`
- `const int *const r` — заморожены **обе стороны**: ни записать значение, ни перенаправить. Не скомпилируются и `*r = 5;`, и `r = &y;`.

Все четыре запретные строки собраны в одном файле и предъявлены компилятору — получены четыре ошибки (контекстные строки листинга опущены, сообщения дословны):

```
constcombo_bad.c: In function 'main':
constcombo_bad.c:9:8: error: assignment of read-only location '*p'
constcombo_bad.c:10:7: error: assignment of read-only variable 'q'
constcombo_bad.c:11:8: error: assignment of read-only location '*(const int *)r'
constcombo_bad.c:12:7: error: assignment of read-only variable 'r'
```

«Значение» компилятор называет *read-only location* (ячейка только для чтения), «сам указатель» — *read-only variable* (переменная только для чтения); у `r` в первом сообщении виден даже его двойной статус — `*(const int *)r`. А вот **разрешённые** операции для тех же типов работают:

```c
#include <stdio.h>

int main(void)
{
    int x = 1, y = 2;

    const int *p = &x;
    p = &y;                       // сам p не const — перенаправлять можно
    printf("*p = %d\n", *p);

    int *const q = &x;
    *q = 5;                       // значение через q менять можно
    printf("x  = %d\n", x);

    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra constcombo_ok.c -o constcombo_ok
./constcombo_ok
```

```
*p = 2
x  = 5
```

**Ответ:** `const int *p` — нельзя менять значение (`*p = 5;` не скомпилируется); `int *const q` — нельзя менять сам указатель (`q = &y;` не скомпилируется); `const int *const r` — нельзя ни то, ни другое (`*r = 5;` и `r = &y;` — обе ошибки). Позиция `const` относительно `*` решает, какая сторона заморожена.

### Г6.Ч3.З5

**Условие.** *(понимание)* Объясните, почему `void *v = &x;` (при `int x`) допустимо, а `printf("%d\n", *v);` — нет. Как правильно напечатать значение по `v`?

**Решение.** `void *` — «указатель на что угодно»: класть в него адрес любого объекта разрешено (преобразование неявное, §6.3.2). Но у `void` нет ни размера, ни трактовки — компилятор не знает, **сколько байт** читать по адресу и **как их понимать**, поэтому разыменование `*v` запрещено. Проверено сборкой ⛔-версии:

### Г6.Ч3.З6

**Условие.** *(понимание)* В коде компаратор написан как `return x - y;`. Объясните, при каких входных данных это даст **неверный** знак, и почему `(x > y) - (x < y)` надёжнее (§6.3.3, переполнение — §2.2).

```c
int cmp(const void *a, const void *b) {
    int x = *(const int*)a, y = *(const int*)b;
    return x - y;
}
```

**Решение.** Компаратору нужен только **знак**, но `x - y` вычисляет полную разность — а она может **не поместиться в `int`**. Математическая разность двух `int` лежит в диапазоне примерно `±4.29 млрд`, тогда как `int` вмещает лишь `±2 147 483 647` (§2.2). Пример: `x = 1500000000`, `y = -1500000000` — истинная разность `3 000 000 000 > INT_MAX`. Это знаковое переполнение — неопределённое поведение (§2.2, глава 13); на практике результат обычно «заворачивается» в отрицательный, и компаратор сообщает `x < y`, хотя на деле `x` больше. `qsort` с таким компаратором тихо выдаёт неверный порядок именно на больших по модулю числах. Мы собрали наивную версию эталонной командой — **ни одного предупреждения** (потенциальное переполнение в чужих данных компилятор предвидеть не может); запуск не приводим — результат зависит от неопределённого поведения.

Выражение `(x > y) - (x < y)` ничего не вычитает: два сравнения дают `0`/`1`, их разность — всегда `-1`, `0` или `1`. Переполнения нет ни при каких входных данных. Проверка на тех самых крайних значениях:

```c
#include <stdio.h>
#include <stdlib.h>

int cmp_safe(const void *a, const void *b)
{
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);     // только знак: переполнения нет
}

int main(void)
{
    int a[3] = {1500000000, -1500000000, 0};   // крайние значения
    qsort(a, 3, sizeof(int), cmp_safe);
    for (int i = 0; i < 3; i++)
        printf("%d ", a[i]);
    printf("\n");
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra cmpsign.c -o cmpsign
./cmpsign
```

```
-1500000000 0 1500000000
```

**Ответ:** `x - y` даёт неверный знак, когда истинная разность выходит за диапазон `int` (например, `x = 1500000000`, `y = -1500000000`): знаковое переполнение — неопределённое поведение, знак результата непредсказуем. `(x > y) - (x < y)` возвращает `-1/0/1` из двух сравнений без вычитания — переполнение невозможно, порядок корректен на любых `int` (прогон выше: крайние значения отсортированы верно).

### Г6.Ч3.З7

**Условие.** *(понимание)* Объясните разницу между `int *f(int, int);` и `int (*f)(int, int);`. Что из них — функция, что — указатель на функцию, и почему скобки меняют смысл?

**Решение.** Разница — в том, к чему «прилипает» звёздочка:

- `int *f(int, int);` — объявление **функции** `f`, принимающей два `int` и возвращающей `int *` (указатель на int). Скобки вызова `(int, int)` связываются с именем `f` раньше звёздочки, и звёздочка достаётся возвращаемому типу: «`f` — функция … возвращающая указатель на `int`».
- `int (*f)(int, int);` — объявление **переменной** `f` типа «указатель на функцию (int, int) → int». Скобки вокруг `*f` насильно связывают звёздочку с именем: сначала «`f` — указатель», потом «…на функцию из двух `int` в `int`».

Скобки меняют **порядок разбора** объявления: без них «функция, возвращающая указатель», с ними — «указатель на функцию». Что первое объявление — именно функция, показывает и компилятор: попытка «инициализировать» его как переменную отвергается —

```
fptr_decl_bad.c:3:1: error: function 'f' is initialized like a variable
    3 | int *f(int, int) = add;    // f объявлена как ФУНКЦИЯ — «присвоить» ей нельзя
      | ^~~
```

**Ответ:** `int *f(int, int);` — функция, возвращающая `int *`; `int (*f)(int, int);` — указатель на функцию `(int, int) → int`. Скобки перетягивают звёздочку от возвращаемого типа к имени: `(*f)` читается «f — указатель», и лишь затем подключается сигнатура. Указателю на функцию скобки обязательны.

### Г6.Ч3.З8

**Условие.** *(прикладное)* Напишите функцию `int apply(int x, int (*f)(int))`, применяющую переданную функцию к `x`. Определите `int cube(int x)` (куб) и `int dbl(int x)` (удвоение) и проверьте: `apply(3, cube)` → `27`, `apply(3, dbl)` → `6`.

**Решение.** `apply` — минимальный «приёмник поведения» (callback, §6.3.3): параметр `f` — указатель на функцию `int → int`, тело — один вызов `f(x)`. Имя переданной функции распадается в адрес само, `&` не нужен.

```c
#include <stdio.h>

int cube(int x) { return x * x * x; }
int dbl(int x)  { return 2 * x; }

int apply(int x, int (*f)(int))       // f — переданное «действие»
{
    return f(x);
}

int main(void)
{
    printf("apply(3, cube) = %d\n", apply(3, cube));
    printf("apply(3, dbl)  = %d\n", apply(3, dbl));
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra applyf.c -o applyf
./applyf
```

```
apply(3, cube) = 27
apply(3, dbl)  = 6
```

**Ответ:** `27` и `6`. Одна и та же `apply` выполняет любое переданное преобразование — действие приходит параметром, как данные.

### Г6.Ч3.З9

**Условие.** *(прикладное)* Отсортируйте массив `int a[7] = {9, 1, 5, 3, 8, 2, 7};` по **возрастанию** с помощью `qsort`, написав компаратор `cmp_asc(const void *, const void *)` со знаковой разностью `(x>y)-(x<y)`. Напечатайте результат (ожидается `1 2 3 5 7 8 9`).

**Решение.** `qsort` получает массив, число элементов, размер одного элемента и компаратор (§6.3.3). Компаратор обязан иметь сигнатуру `int (const void *, const void *)`: внутри приводим `const void *` к `const int *` (тип знаем мы, не `qsort`), разыменовываем и возвращаем знак через безопасную формулу `(x > y) - (x < y)` (Г6.Ч3.З6).

```c
#include <stdio.h>
#include <stdlib.h>

int cmp_asc(const void *a, const void *b)
{
    int x = *(const int *)a;      // void* -> const int*, затем значение
    int y = *(const int *)b;
    return (x > y) - (x < y);     // -1 / 0 / 1: только знак
}

int main(void)
{
    int a[7] = {9, 1, 5, 3, 8, 2, 7};
    qsort(a, 7, sizeof(int), cmp_asc);   // массив, длина, размер элемента, компаратор
    for (int i = 0; i < 7; i++)
        printf("%d ", a[i]);
    printf("\n");
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra qsortasc.c -o qsortasc
./qsortasc
```

```
1 2 3 5 7 8 9
```

**Ответ:** `1 2 3 5 7 8 9`. `qsort` переставляет элементы, сверяясь с нашим `cmp_asc`: отрицательный результат — `x` раньше `y`, положительный — позже.

### Г6.Ч3.З10

**Условие.** *(прикладное)* На основе предыдущей задачи напишите компаратор `cmp_desc`, сортирующий тот же массив по **убыванию** (ожидается `9 8 7 5 3 2 1`). Подсказка: поменяйте местами роли `x` и `y` в знаковой разности. Убедитесь, что сама `qsort` и массив не менялись — изменился только компаратор.

**Решение.** Порядок сортировки целиком задаёт компаратор: меняем в знаковой разности роли `x` и `y` — `(y > x) - (y < x)` — и «больший раньше». Вызов `qsort` и массив — дословно те же, что в Г6.Ч3.З9.

```c
#include <stdio.h>
#include <stdlib.h>

int cmp_desc(const void *a, const void *b)
{
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (y > x) - (y < x);     // роли x и y поменяны: порядок обратный
}

int main(void)
{
    int a[7] = {9, 1, 5, 3, 8, 2, 7};
    qsort(a, 7, sizeof(int), cmp_desc);  // та же qsort, тот же массив
    for (int i = 0; i < 7; i++)
        printf("%d ", a[i]);
    printf("\n");
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra qsortdesc.c -o qsortdesc
./qsortdesc
```

```
9 8 7 5 3 2 1
```

**Ответ:** `9 8 7 5 3 2 1`. Универсальный сортировщик не изменился ни на символ — сменилась только «инструкция сравнения», и порядок развернулся: правило порядка живёт в компараторе.

**Вариант 2 (обмен аргументов).** Убывание можно получить, вообще не переписывая формулу — вызвав готовый `cmp_asc` с переставленными аргументами:

```c
#include <stdio.h>
#include <stdlib.h>

int cmp_asc(const void *a, const void *b)
{
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);
}

int cmp_desc(const void *a, const void *b)
{
    return cmp_asc(b, a);         // убывание = возрастание с обменом аргументов
}

int main(void)
{
    int a[7] = {9, 1, 5, 3, 8, 2, 7};
    qsort(a, 7, sizeof(int), cmp_desc);
    for (int i = 0; i < 7; i++)
        printf("%d ", a[i]);
    printf("\n");
    return 0;
}
```

```
gcc -std=c17 -Wall -Wextra qsortdesc_swap.c -o qsortdesc_swap
./qsortdesc_swap
```

```
9 8 7 5 3 2 1
```

*Сравнение.* Прямая формула `(y > x) - (y < x)` самодостаточна и не требует второй функции; обёртка `cmp_asc(b, a)` переиспользует уже проверенный компаратор и выражает общий приём «обратный порядок = поменять аргументы местами», который работает для *любого* компаратора (строкового, вещественного), не вникая в его формулу. В большом коде обёртка предпочтительнее: одна логика сравнения — один источник истины.
